# 用户代码 review 与手动验收

本次实现与修复授权已收到；用户随后明确要求提交并推送到指定仓库，按该次授权执行 Git 发布。自动验证和推送不代替真实账号验收。仅在准备好实际发送时运行 worker。

| 验收项 | 实现位置 | 自动验证 / 真实验收 |
| --- | --- | --- |
| AC1 固定账号和手动作品，作者不匹配时不发送 | `src/douyin/adapter.js`、油猴 dispatcher、`src/worker.js` | 自动覆盖身份切换/其他作者；真实需用当前账号只读核验一个自己的作品和一个其他作者作品 |
| AC2 回复自己评论、真实 @ 自己、明确向大肥鱼提问；不抢其他观众对话 | `adapter.js`、`agent/trigger.js`、`agent/reply.js` | 结构及输出契约已模拟；入站字段语义、语义识别准确率需实测，关系开关默认关闭 |
| AC3 历史分轮处理、旧楼新回复、实际目标去重 | `adapter.js` continuation、`store.js`、`worker.js` | 自动覆盖分轮/续扫/重启、历史已回填和 pending 更新；实际热度分页仍可能变动 |
| AC4 固定人格与完整问题，模型不能更改目标 | `prompts/`、`agent/` | 自动覆盖结构化契约、已知回复他人的反证、直接父链及异常；实际语言质量与理解准确性需人工读结果 |
| AC5 文字与可选素材，目标楼层和图片须有回执 | `stickers/service.js`、`worker.js`、`adapter.js` | 真实包离线检索已验证，图片上传仅模拟；GIF 显示、图片权限及楼中楼位置待实测 |
| AC6 发送不确定时不重发，队列和配额持久化 | `store.js`、`lock.js`、`worker.js` | 自动覆盖断回执、sending恢复、锁、每轮额度与间隔 |

建议真实验收顺序：

1. 只启动 Bridge，安装油猴并运行 doctor；不要启动 worker。检查 UID 和作品作者。
2. inspect 查看已有回复/@样本与反例，对照浏览器核查关系映射。存在差异先修适配并测试。
3. 填写模型密钥，选一个自己的测试作品。首次真实发送将 `maxRepliesPerRound` 调为 1，保留发送间隔，先关闭表情。
4. 运行 once，查看拟响应场景、平台实际回复位置、身份、语气和 status；同一目标再次运行不能重发。
5. 分别测试被回复、被 @、未点名但明确向大肥鱼提问，以及同楼观众互聊和 @ 他人的反例；覆盖旧父楼下的新回复。
6. 再开启表情，只验证一条文字配 GIF 回复。检查图片内容、数量、动画与其他客户端显示。
7. 模拟关闭 Bridge/切换登录账号，再检查 worker 不会换号发布；不确定状态保留核查，不直接重试。

以上步骤尚未由用户执行。确认结果只适用于对应代码和配置版本。本次 Git 发布已有用户明确授权；未来提交按届时授权范围执行。
